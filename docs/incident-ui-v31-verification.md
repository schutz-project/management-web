# 사건 관리 UI v3.1 구현·검수

기준: 전달된 v3.1 최종 요구사항과 메인·상세 참고 이미지.
이 문서는 개발 브랜치 검수 결과이며 운영 반영 완료를 의미하지 않습니다.

## 범위

- P0: 기존 인증·CSRF·사건 상태 전이·조치 기록·종료 정책을 유지하면서 목록과 넓은 상세 패널을 개선합니다.
- 목록 요약은 검색·심각도 조건에 맞는 전체 기간의 모든 상태 집계입니다. 목록 총건수는 탭·상태 조건도 반영합니다. 상단 지표 기간 선택은 사건 집계에 적용되지 않음을 표시합니다.
- 심각도는 저장된 Prometheus 근거의 warning/critical만 사용합니다. 원본이 없으면 미제공입니다.
- 현재 상태는 별도 dashboard 조회 결과이며 과거 사건의 근거·AI 입력과 분리합니다. Web에서 Worker 설정을 확인하지 못하면 기능 상태 미확인입니다.
- DB 스키마·Worker 과거 이력 선택 로직·인프라는 변경하지 않습니다.

## 자동 검증

- `node --test tests/test-monitoring-ui.cjs`: 58개 통과. DOM 대역 기반 회귀 테스트이며 실제 브라우저 렌더링 검증과 구분합니다.
- Python unittest: 사건 쓰기 5개, 사건 목록 7개, Prometheus 종료 정책 3개, 총 15개 통과.
- PostgreSQL SQL 생성 검증 포함. 로컬 실행 DB는 SQLite이며 실제 PostgreSQL 실행 검증은 포함하지 않습니다.
- CI에 사건 목록 검증을 추가하여 이미지 내부에서 기존 API·정책 검증과 함께 실행합니다.
- 직접 조회가 Target 행을 생성하지 않는지, 권한·검색 입력·실제 전송 메타데이터를 검증합니다.

## 배포 전 확인

1. 실제 브라우저에서 참고 이미지 대비 레이아웃, 작은 화면, Tab 이동·포커스와 Clipboard 권한을 확인합니다.
2. 운영 계약의 현재 점검 상태·심각도·시도 시각이 미제공일 때 안내가 정확한지 확인합니다.
3. 검토 승인 후 병합·배포합니다. 운영 사건 종료·Slack·AI 재호출을 검수 목적으로 자동 실행하지 않습니다.

## 2026-10-26 Chromium 화면 검수

PR 개발 CI의 격리된 127.0.0.1 서버에서 저장소의 실제 HTML/CSS/JS와 검수용 API 응답을 사용합니다. 운영 데이터·AWS·Slack·AI 호출은 없습니다. 캡처는 디자인 생성 이미지가 아니라 Chromium 렌더링입니다.

- 화면: 데스크톱 1440×1000, 모바일 390×844.
- 사건 목록, 상세 상단, AI·과거 이력·Slack 3종·탐지 근거·조치·종료 영역별 PNG를 CI의 `incident-ui-v31-review` 아티팩트로 보존합니다.
- 발견/수정: 모바일 페이지 가로 넘침(503px→390px), 공통 dialog 버튼 스타일로 인한 ID 복사·목록 복귀 버튼 정렬, 모바일 검수 안내 배지의 콘텐츠 가림.
- 브라우저 동작: 목록 복귀, 과거 원본 이동 및 뒤로가기, 기존 초안 입력 시 자동 저장하지 않음, 409 시 조치 입력 보존·단일 POST, 종료 미충족 버튼 비활성, 신규 접수 버튼 노출, JavaScript 오류 검사를 실행합니다.
- 테스트용 POST는 격리 서버의 409 응답입니다. 실제 운영 사건 접수·종료·외부 알림까지 성공했다는 의미는 아닙니다. 실제 API의 상태 전이·권한·종료 정책은 별도 Python 테스트로 검증합니다.
- CI는 브랜치에서 캡처·테스트만 수행합니다. 병합·운영 배포는 계속 보류합니다.

개발 PC에서 재현하려면 별도 임시 디렉터리에 Playwright 1.56.1과 Chromium을 설치하고, 해당 모듈 디렉터리를 NODE_PATH로 지정해 `node tests/capture-incident-ui.cjs`를 실행합니다. 검수 서버는 스크립트가 임의 포트의 127.0.0.1에 만들고 종료합니다. 출력은 `artifacts/incident-ui-v31/`입니다.

## 추가 데스크톱 피드백 반영

이번 검수의 필수 범위는 데스크톱 1440px·1280px입니다. 모바일 전용 카드 및 전체 화면 상세는 구현·검수 범위에서 제외합니다. 이전 모바일 기초 스타일은 유지합니다.

- 상세 상단: 현재 기능 점검을 먼저 표시하고 관측 시각·조회 시각·출처를 메타데이터로 구분합니다. Prometheus 평가는 별도 칸, 운영 판단 안내는 높이가 늘어나지 않는 간결한 행으로 정리합니다.
- 조치·종료: 초안/저장/종료 의미와 색상을 구분하면서 44px 이상 높이·간격·정렬을 통일합니다. 상세의 중복 닫기를 제거합니다. 서버 정책과 409 입력 보존은 변경하지 않습니다.
- 목록: 동일 서버 검색·필터·총건수 정책을 유지하고 1280px에서 표 열과 버튼이 겹치거나 가려지지 않도록 점검합니다.
- 브라우저 캡처·검증은 1440×1000과 1280×900에서 수행합니다. 운영 데이터·권한·외부 알림 검증과 구분하고, 병합·배포는 보류합니다.

## 최종 조건부 검수 반영 및 배포 보류

- 데스크톱 보조 설명·관측 메타데이터·시도 이력·목록 보조 문구를 최소 13px로 조정하고 진한 색상으로 대비를 보강합니다. 각 상태 배지는 기존 의미와 배경색을 유지하면서 글자 대비를 조정합니다.
- 긴 상세의 섹션 바로가기는 필수 범위가 아닌 후속 개선입니다. 모바일 최적화도 제외합니다.
- API·권한·사건 종료 조건은 기존 검증을 유지하고 최신 커밋 CI와 Chromium 결과를 확인한 뒤 병합합니다.
- 이번 squash 병합 커밋에 `[skip deploy]`를 명시합니다. CI의 EC2 배포 job이 이 표식을 검사하므로 테스트·이미지 게시 후에도 EC2 배포는 건너뜁니다. 일반 커밋의 기존 자동 배포 동작과 수동 workflow_dispatch는 유지합니다.
- 운영 배포는 별도 승인 후 진행합니다. 실제 운영 데이터의 검증은 격리 API 화면·기능 검수와 구분합니다.
