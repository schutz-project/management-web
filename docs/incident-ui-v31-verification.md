# 사건 관리 UI v3.1 구현·검수

기준: 전달된 v3.1 최종 요구사항과 메인·상세 참고 이미지.
이 문서는 개발 브랜치 검수 결과이며 운영 반영 완료를 의미하지 않습니다.

## 범위

- P0: 기존 인증·CSRF·사건 상태 전이·조치 기록·종료 정책을 유지하면서 목록과 넓은 상세 패널을 개선합니다.
- 목록 요약은 검색·심각도 조건에 맞는 전체 기간의 모든 상태 집계입니다. 목록 총건수는 탭·상태 조건도 반영합니다. 상단 지표 기간 선택은 사건 집계에 적용되지 않음을 표시합니다.
- 심각도는 저장된 Prometheus 근거의 warning/critical만 사용합니다. 원본이 없으면 미제공입니다.
- 현재 상태는 별도 dashboard 조회 결과이며 과거 사건의 근거·AI 입력과 분리합니다. Web에서 Worker 설정을 확인하지 못하면 기능 상태 미확인입니다.
- DB 스키마·Worker 과거 이력 선택 로직·인프라는 변경하지 않습니다.

## 자동 검증

- `node --test tests/test-monitoring-ui.cjs`: 58개 통과. DOM 대역 기반 회귀 테스트이며 실제 브라우저 렌더링 검증과 구분합니다.
- Python unittest: 사건 쓰기 5개, 사건 목록 7개, Prometheus 종료 정책 3개, 총 15개 통과.
- PostgreSQL SQL 생성 검증 포함. 로컬 실행 DB는 SQLite이며 실제 PostgreSQL 실행 검증은 포함하지 않습니다.
- CI에 사건 목록 검증을 추가하여 이미지 내부에서 기존 API·정책 검증과 함께 실행합니다.
- 직접 조회가 Target 행을 생성하지 않는지, 권한·검색 입력·실제 전송 메타데이터를 검증합니다.

## 배포 전 확인

1. 실제 브라우저에서 참고 이미지 대비 레이아웃, 작은 화면, Tab 이동·포커스와 Clipboard 권한을 확인합니다.
2. 운영 계약의 현재 점검 상태·심각도·시도 시각이 미제공일 때 안내가 정확한지 확인합니다.
3. 검토 승인 후 병합·배포합니다. 운영 사건 종료·Slack·AI 재호출을 검수 목적으로 자동 실행하지 않습니다.
