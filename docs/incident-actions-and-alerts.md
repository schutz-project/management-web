# 경보·사건 구분 및 관리자 사건 처리 복원

## 문제와 변경

새 UI는 로컬 미리보기의 `/local/status`가 없으면 조회 전용으로 남았습니다. 운영 관리자 API에 접수·조치·종료 기능이 있어도 화면에서 접근할 수 없었습니다. 종 모양 패널은 현재 Prometheus 경보만 보여, 모의 사건이나 복구 후 미종료 사건이 있어도 경보가 없다는 문구만 표시했습니다.

- 인증된 관리자 전용 `GET /api/management/capabilities`를 추가합니다. 운영 UI는 관리자 로그인 확인 후 이 응답으로 사건 처리 버튼 표시 여부를 판단합니다. 조회 실패·기존 서버의 404 응답은 조회 전용으로 유지합니다.
- `MANAGEMENT_ACTIONS_ENABLED` 기본값은 true입니다. false일 때는 버튼뿐 아니라 접수·조치·종료 API도 차단합니다. 조회 API는 유지합니다. 관리자 세션·CSRF·Origin 검사·기존 사건 상태 전이는 그대로 적용합니다.
- 로컬 미리보기의 명시적 조회 전용 설정과 저장본 모드는 유지합니다. 페이지 조회·초안 작성으로 사건을 자동 접수하거나 저장·종료하지 않습니다.
- 경보 패널에서 실시간 Prometheus 경보 수와 관리 DB의 미종료 사건 수를 나란히 표시합니다. 패널을 열 때 두 상태를 다시 조회하고 실패는 0이 아닌 미확인으로 표시합니다. 사건 목록 이동 버튼을 제공합니다.
- 사건 상세의 접수, 조치 기록, 조치·종료 근거 초안을 상태별로 연결합니다. 별도 문서 내보내기나 완성 보고서 생성 기능을 추가하는 변경은 아닙니다.

## 모의 알림 시험의 종료

`notification_delivery_test`이며 `synthetic=true`인 사건에만 별도 종료 기준을 적용합니다. 실제 장애 복구로 해석하지 않습니다.

1. 관리자가 접수하고 조치 기록을 작성합니다.
2. 최초 Slack·AI 분석·AI 완료 Slack이 모두 live 모드에서 succeeded여야 합니다.
3. 두 Slack 작업은 sent=true, AI 작업은 저장된 요약이 있어야 합니다.
4. 관리자가 시험 종료를 확인하고 종료 근거를 입력해 직접 종료합니다.

다른 장애·보안·Prometheus 규칙의 복구 조건은 유지합니다. 실제 장애로 표시된 같은 규칙에는 모의 시험 예외를 적용하지 않습니다. Worker의 수집·탐지·알림 처리는 수정하지 않습니다. 이번 Web의 domain.py 변경은 화면/API의 종료 판단 범위이며 Worker와 완전히 동일한 파일은 아니게 됩니다.

## 초안의 표현

모의 알림 시험의 처리 성공은 실제 장애 복구와 구분합니다. Prometheus 사건은 해당 복구 조건을 설명합니다. 초안은 빈 입력칸을 채우는 보조 기능이며 담당자가 실제 수행 내용을 검토한 뒤 저장해야 합니다. AI 원문을 자동 번역하거나 재호출하지 않습니다.

## 검증

- Node 기반 UI·회귀·초안 41개: 관리자 처리 연결, 조회 전용 유지, 권한 조회 실패, 경보·사건 구분, 조회 실패, 수동 접수·조치·종료와 CSRF 요청, 초안의 표현 검사.
- 실제 FastAPI 앱과 임시 SQLite를 이용한 API 시험 5개: 비로그인·일반 계정 차단, CSRF·Origin 검사, 서버 비활성화 차단, 수동 접수→조치→종료, 모의 전송 조건과 실제 장애 구분.
- 기존 Prometheus 종료 정책 3개 유지.
- 외부 AI·Slack·AWS 호출 없이 시험합니다. 운영 PostgreSQL과 실제 브라우저의 배치·입력은 승인 후 배포 시 추가 확인이 필요합니다. 로컬 FastAPI 0.162/SQLAlchemy 2.0에서 검사했고 CI는 저장소의 고정 의존성으로 재검증합니다.

## 배포·복구

현재 단계는 PR 검토까지입니다. 병합·배포와 운영 사건 변경은 수행하지 않습니다. 승인 후 현재 Web 이미지와 Compose·환경 설정을 기록하고 Web만 배포합니다. Worker·DB·네트워크·HTTPS 설정은 변경하지 않습니다.

기준 main 커밋: d89aa483e998b580ad2582a5b8d94c578f4da324.

배포 후 문제가 있으면 기존 Web 이미지로 복구합니다. DB 스키마 변경은 없습니다. 다만 관리자가 저장한 접수·조치·종료 이력은 코드 롤백으로 삭제되거나 되돌아가지 않습니다. 처리 기능만 보류하려면 MANAGEMENT_ACTIONS_ENABLED=false로 Web을 재생성합니다. 운영 환경 파일 변경은 별도 승인된 배포 단계에서 진행합니다.
