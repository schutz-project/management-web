# 두 서버 대시보드 브라우저 검수

이 검수는 격리된 loopback 서버의 **가상 데이터만** 사용한다. AWS·EC2·Prometheus·실서비스에 접속하지 않고 쓰기 API도 호출하지 않는다. 운영 화면의 실제 데이터 수집 성공을 증명하는 검사는 별도다.

## 실행

브라우저가 설치된 개발 PC에서 `management-web` 저장소 루트로 이동한 뒤 실행한다.

```bash
npm install --no-save playwright
npx playwright install chromium
node tests/capture-dual-host-ui.cjs
```

성공 시 `PASS: 1440/390px ...`를 출력한다. 실패하면 첫 오류·실행 환경·현재 커밋을 기록한다. 이 스크립트는 스크린샷을 자동 저장하지 않는다. 화면을 직접 보려면 Playwright의 `headless:false`를 로컬에서 임시로 적용하고 서비스·모니터링 카드, 상세의 역할·주소, 사용자 지정 기간과 새로고침을 추가 확인한다.

| 확인 항목 | 기대 결과 | 결과 |
| --- | --- | --- |
| 1440px / 390px 카드 선택 | 두 카드, 모니터링 서버 선택 시 CPU 55% 가상값 | 미실행 |
| 상세 이동·새로고침 | URL에 선택 host 보존, 동일 서버 재표시 | 미실행 |
| stale | 수집 지연, 현재값 0%로 대체하지 않음 | 미실행 |
| no_data | 수집 대상 미설정, 현재값 0%로 대체하지 않음 | 미실행 |
| 안전성 | 모든 페이지에서 브라우저 JS 오류 0, 외부 요청 0, 비 GET 요청 0; 요청 전 차단 | 미실행 |
| 사용자 지정 기간 | KST 입력에서 계산한 UTC가 URL·API에 일치하고 새로고침 뒤 서버·기간·API 요청 유지 | DOM 회귀 테스트 통과, Playwright 후보 검사 추가·실제 브라우저 미검수 |

브라우저 검수 성공 후에도 실제 서버 측 역할 라벨·지표 표본·운영 Compose 검증은 따로 완료해야 한다.

후보 `ci.yml`의 기존 Playwright 설치 단계 뒤에 이 로컬 fixture 검수를 연결했습니다. 해당 CI 성공은 가상 데이터에 대한 브라우저 동작 근거이며, 운영 UI·Prometheus 실측을 뜻하지 않습니다. 실제 CI 실행 URL과 커밋 SHA는 PR 생성 후 기록합니다.

별도 `tests/check-dual-host-browser-failures.cjs`를 같은 CI 브라우저 단계에 한 번 더 실행하도록 연결했습니다. 역할 메타데이터 조회 실패, CPU 단독 실패, 호스트 전체 조회 불가, 키보드 탭·뒤로/앞으로·새로고침 복원을 1440/390px에서 확인합니다. 상대가 Playwright 1.56.1 / Chromium build 1194에서 8/8 통과했다고 보고했으며, 이 작업 공간에서는 Chromium 실행 파일이 없어 독립 실행 결과로 합산하지 않습니다. 이 검사와 위 사용자 지정 기간 확장 검사의 역할은 별개입니다.
