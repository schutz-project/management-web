# 로컬 검증 UI의 Management Web 반영

## 변경 범위

- 기본 화면과 사건 상세 진입 경로를 `static/schutz-ui/index.html`로 연결합니다.
- 기존 로그인·지표·사건·로그 API를 사용하며 인증 및 DB 계약은 변경하지 않습니다.
- 서비스 메뉴 펼침, 서비스별 지표, 기간별 조회, 수집 상태·설정·알림 가독성, 뒤로가기·새로고침 복원을 반영합니다.
- 기존 `static/manage.html`, `manage.js` 등은 보존합니다.
- 새 UI는 기본 조회 전용입니다. 사건 접수·조치·종료 버튼은 비활성화합니다. 기존 API 권한은 그대로이며 서버 차원의 쓰기 차단은 아닙니다.
- 과거 AI 결과는 저장된 원문을 표시합니다. 자동 번역·재분석·Slack 재전송은 실행하지 않습니다.
- 로컬 프록시, 인증서, 실제 사건 내보내기 파일은 배포하지 않습니다. 서버에서는 동일 출처 API를 직접 호출합니다.
- Terraform, HTTPS·포트·Compose, Worker, FastAPI는 이번 PR의 변경 대상이 아닙니다.

## 검증

- 사용자가 로컬 UI와 실제 서버를 연결해 로그인, 기간별 조회, 서비스 지표, 사건 상세·AI 결과·로그, 뒤로가기·새로고침을 확인했습니다.
- Node 회귀 시험으로 API 연결·CSRF·조회 전용·기간 전달·메뉴·이력 복원을 검사합니다.
- 시험 데이터는 테스트 폴더의 합성 fixture입니다. 실제 사건 ID와 AI 결과는 제외했습니다.
- PR CI에서 기존 화면·배포 검사와 새 UI 시험을 함께 실행합니다.
- 서버 직접 배포 후의 로그인·정적 파일·CSP 및 실제 화면 확인은 아직 수행하지 않았습니다.

## 복구 기준과 절차

기준 커밋: `29ed32394917417f7933a502ef1580e2ca83e7f9`

보존 브랜치: `checkpoint/pre-ui-feedback-20261025`

이 기준은 Management Web 코드입니다. AWS·DB 전체의 시점 백업은 아닙니다. 사용자 피드백으로 원상복구할 때는 이 PR을 되돌리는 별도 PR을 검토 후 병합하고, 기존 CI/CD로 Web을 재배포합니다. DB 마이그레이션이 없으므로 사건·조치 데이터 복원은 필요하지 않습니다.

배포 직전에는 실행 중인 Web 이미지 태그를 별도로 기록하고 ECR에 보존됐는지 확인합니다. 긴급 이미지 복구는 해당 태그를 명시하는 기존 Web 단일 서비스 배포 절차를 사용하고 HTTPS 추가 Compose 설정과 Worker·DB를 유지합니다. 배포 완료 후의 사용성 피드백은 자동 롤백 대상이 아니므로 수동 복구를 요청해야 합니다.

병합 및 실제 배포는 사용자 승인 이후에 진행합니다.
